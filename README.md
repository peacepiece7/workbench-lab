# workbench-lab

**AI Native Lab — 설계하고 실험하며 배우는 AI 서비스 개발 기초**

프롬프트를 잘 쓰는 것에서 한 걸음 더 나아가, 근거·도구·권한·평가·운영 조건을 갖춘 AI 시스템을 이해하기 위한 한국어 학습 실험실입니다.

[배포된 학습 사이트](https://ai-native-learning-lab.scv7282.chatgpt.site)

배포된 사이트는 Sites에서 소유자만 접근하도록 설정되어 있습니다. 사이트 접근 권한과 GitHub 저장소의 공개 범위는 서로 독립적입니다. 이 소스 코드를 다른 곳에 배포하면 기존 사이트의 접근 제한이 자동으로 적용되지 않습니다.

## 학습 방식

1. 왼쪽 학습 경로에서 실험을 선택합니다.
2. 기본 설계로 **실험 실행**을 눌러 실패 사례를 확인합니다.
3. 설계 변수를 하나씩 바꾸며 이전 결과와 비교합니다.
4. **개념 노트**에서 원리와 실험의 가정을 읽습니다.
5. 현재 설계로 4개 테스트를 모두 통과하고 **이해도 확인** 퀴즈를 맞히면 해당 실험이 완료됩니다.

설정을 변경한 뒤에는 이전 실행 결과가 남아 있음을 표시합니다. 변경한 설계를 검증하려면 다시 실행하세요. 학습 순서는 권장 순서이며, 모든 실험에 바로 접근할 수 있습니다.

## 6개의 교육용 시나리오

| 실험 | 상황 | 학습 내용 |
| --- | --- | --- |
| 프롬프트와 컨텍스트 | 환불 규정을 지어내는 상담봇 | 근거 제공, 출력 계약, 답변 보류 |
| 검색 증강 생성 · RAG | 구버전 사내 규정을 인용하는 도우미 | 키워드·의미 검색, 문서 유효성, 근거 확인 |
| 도구 호출과 안전 | 배송 조회와 환불 실행 | 입력 검증, 소유권 확인, 사용자 승인 |
| 워크플로와 에이전트 | 검색을 멈추지 못하는 리서치 도우미 | 실행 구조, 반복 한도, 실패 인계 |
| 평가와 품질 관리 | 데모에서는 좋지만 운영에서 실패하는 상담봇 | 대표 테스트셋, 업무 기준, 치명적 실패 차단 |
| 비용과 응답 시간 | 모든 요청에 같은 자원을 쓰는 고객센터 | 모델 분기, 컨텍스트 축소, 캐시 격리 |

총 **24개 시나리오 테스트**, **6개 이해도 문제**, 주제별 개념 노트와 공식 문서 링크가 포함되어 있습니다.

## 중요한 한계

- **실제 AI 모델을 호출하지 않습니다.** API 키 없이 동작하는 결정론적 규칙 기반 시뮬레이션입니다.
- 테스트 통과는 해당 교육 시나리오의 조건을 만족했다는 뜻입니다. 실제 모델의 정확도, 안전성, 비용, 지연을 보장하거나 예측하지 않습니다.
- 모델 배정과 검색 성능 등은 학습을 위한 가정입니다. 실제 서비스에는 별도의 대표 평가셋과 운영 검증이 필요합니다.
- 학습 진행과 설계 상태는 현재 페이지 세션에만 유지됩니다. **새로고침하면 초기화**되며 계정 간 동기화나 데이터베이스 저장은 없습니다.
- 사이트의 소유자 전용 접근 제어는 배포 플랫폼에서 처리합니다. 앱 자체에 로그인 기능을 구현한 것은 아닙니다.

## 로컬 실행

Node.js **22.13 이상**과 npm이 필요합니다. Node.js 24 환경에서 검증했습니다.

```bash
git clone https://github.com/peacepiece7/workbench-lab.git
cd workbench-lab
npm ci
npm run dev
```

개발 서버가 출력하는 Local 주소를 브라우저에서 여세요. 기본 주소는 `http://localhost:3000/`이며 포트 사용 여부에 따라 달라질 수 있습니다.

### 검증 및 빌드

```bash
# 시나리오 규칙 검증
node --experimental-strip-types --test tests/course.test.ts

# 타입 검사
npx tsc --noEmit

# 배포용 빌드
npm run build

# 빌드한 Worker를 로컬에서 실행
npm run start
```

추가 명령: `npm run lint`는 정적 분석, `npm run format`은 코드 서식 정리를 수행합니다.

현재 테스트는 19개이며, 학습 자료의 구조, 모든 설계 조합에서 성공 가능한 구성의 존재, 각 변수의 결과 영향, 잘못된 입력 거부를 확인합니다. 검증 범위와 제외 항목은 [VALIDATION.md](./VALIDATION.md)에 기록되어 있습니다.

## 기술 구성

- **React 19 · TypeScript**: 인터페이스와 학습 상태
- **Vinext · Vite**: App Router 방식의 앱 구성과 빌드
- **Tailwind CSS 4 · shadcn/Base UI**: 스타일과 접근성 기반 UI 컴포넌트
- **Lucide**: 인터페이스 아이콘
- **Cloudflare Workers · Sites**: 배포 환경 및 사이트 접근 제어
- **Node.js 기본 테스트 러너**: 시나리오 규칙 검증

별도의 AI API, 데이터베이스, 외부 결제 서비스는 사용하지 않습니다.

## 시나리오 수정

`lib/course.ts`의 `Lesson` 타입을 기준으로 학습 자료를 구성합니다. 현재 화면은 **설계 변수 3개, 테스트 4개**를 전제로 합니다.

각 테스트의 `requires`는 변수별로 허용되는 선택지 인덱스입니다. 빈 배열은 해당 변수가 그 테스트의 판정에 영향을 주지 않는다는 뜻입니다.

```ts
// 첫 번째 변수는 1번 선택지, 두 번째 변수는 어떤 선택지든,
// 세 번째 변수는 0번 또는 2번 선택지일 때 통과합니다.
requires: [[1], [], [0, 2]]
```

선택지 인덱스는 0부터 시작합니다. 시나리오 변경 시 성공 가능한 설계가 존재하는지, 모든 변수가 의미 있는 차이를 만드는지 테스트를 실행하세요. 실험 수나 구조를 바꾸면 화면과 테스트의 고정 조건도 함께 조정해야 합니다.

## 배포와 보안

이 저장소에는 기존 사이트의 연결 정보가 포함되어 있습니다. 별도 사이트를 만들 경우 기존 `.openai/hosting.json`의 프로젝트를 그대로 대상으로 삼지 말고 새 배포 프로젝트를 연결하세요.

GitHub에 push하는 것만으로 Sites가 자동 재배포되지는 않습니다. 현재 사이트는 검증된 빌드 결과를 Sites에 게시하는 방식으로 배포되어 있습니다. README만 변경해도 이미 게시된 웹 화면에는 영향이 없습니다.

API 키, 액세스 토큰, `.env` 파일을 커밋하지 마세요. 현재 앱은 AI API 키를 필요로 하지 않으며, 빌드 출력과 의존성 디렉터리는 `.gitignore`로 제외합니다.

지원되는 브라우저에서는 선택적 WebMCP 도구 `run_learning_experiment`를 노출합니다. 해당 기능은 수동 인터페이스와 같은 실행 동작을 사용하며, 지원되지 않는 브라우저에서도 학습 기능은 사용할 수 있습니다. 라이브 WebMCP 등록·호출 검증 여부는 [VALIDATION.md](./VALIDATION.md)를 참고하세요.
