# workbench-lab

**AI Native Lab — 설계하고 실험하며 배우는 AI 서비스 개발 기초**

프롬프트를 잘 쓰는 것에서 한 걸음 더 나아가, 근거·도구·권한·평가·운영 조건을 갖춘 AI 시스템을 이해하기 위한 한국어 학습 실험실입니다.

[배포된 학습 사이트](https://ai-native-learning-lab.scv7282.chatgpt.site)

배포된 사이트는 Sites에서 소유자만 접근하도록 설정되어 있습니다. 사이트 접근 권한과 GitHub 저장소의 공개 범위는 서로 독립적입니다. 이 소스 코드를 다른 곳에 배포하면 기존 사이트의 접근 제한이 자동으로 적용되지 않습니다.

## v2에서 달라진 점

- **10개 실험**: 기존 6개에 메모리, 프롬프트 인젝션, 재시도·중복 실행, AI 코드 리뷰를 추가했습니다. 평가는 학습 경로 두 번째로 이동했습니다.
- **실행 근거**: 기대 행동과 실제 결과, 단계별 기록, 사용·제외된 문서를 펼쳐 볼 수 있습니다. 모델의 숨겨진 사고 과정이 아닌 교육용 관측 기록입니다.
- **RAG 심화**: 합성 문서 후보에 실제 필터·순위 선택·관련도 임계값을 적용하고 기대 문서와 대조합니다. 근거 중심·빠른 조회·권한 우선 과제의 성공 조건이 다릅니다.
- **평가 심화**: 예시 응답의 평가 판정을 사람이 작성한 기준 답안과 비교합니다. 정상 답변의 오탐, 평가 누락, 치명적 오류를 구분합니다.
- **비교와 이어하기**: 설계 이유, 최근 20회 실행 이력, 설정, 퀴즈 상태를 이 브라우저에 저장합니다. 같은 업무 조건·문제 세트끼리 결과와 작업 단위를 비교합니다.
- **새 상황 복습**: RAG·평가는 최초 실행 전 숨겨진 검증 질문, 나머지 실험은 별도 적용 문제를 제공합니다.

## 학습 방식

1. 왼쪽 학습 경로에서 실험을 선택합니다.
2. 기본 설계로 **실험 실행**을 눌러 실패 사례를 확인합니다.
3. 각 사례를 펼쳐 **기대 행동·실제 결과·실행 기록·근거 자료**를 대조합니다.
4. 설계 이유를 적고 변수를 바꿔 실행합니다. 이전 실행 또는 기록에서 선택한 설계와 비교합니다.
5. **개념 노트**에서 원리와 실험의 가정을 읽습니다.
6. 12자 이상의 설계 이유가 있는 목표 충족 실행, 이해도 정답, 새로운 상황의 복습까지 완료하면 해당 실험이 완료됩니다. 이유는 길이만 검사하며 AI가 의미를 채점하지 않습니다.

RAG·평가의 검증 문제는 현재 설정으로 연습 목표를 충족한 뒤 실행할 수 있습니다. 검증 질문은 UI에서 처음에 숨겨질 뿐 공개 소스에 포함된 교육 자료입니다. 비밀 평가셋으로 사용하면 안 됩니다.

설정을 변경한 뒤에는 이전 실행 결과가 남아 있음을 표시합니다. 변경한 설계를 검증하려면 다시 실행하세요. 학습 순서는 권장 순서이며, 모든 실험에 바로 접근할 수 있습니다.

## 10개의 교육용 시나리오

| 실험 | 상황 | 학습 내용 |
| --- | --- | --- |
| 프롬프트와 컨텍스트 | 환불 규정을 지어내는 상담봇 | 근거 제공, 출력 계약, 답변 보류 |
| 검색 증강 생성 · RAG | 구버전 사내 규정을 인용하는 도우미 | 키워드·의미 검색, 문서 유효성, 근거 확인 |
| 도구 호출과 안전 | 배송 조회와 환불 실행 | 입력 검증, 소유권 확인, 사용자 승인 |
| 워크플로와 에이전트 | 검색을 멈추지 못하는 리서치 도우미 | 실행 구조, 반복 한도, 실패 인계 |
| 평가와 품질 관리 | 데모에서는 좋지만 운영에서 실패하는 상담봇 | 대표 테스트셋, 업무 기준, 치명적 실패 차단 |
| 비용과 응답 시간 | 모든 요청에 같은 자원을 쓰는 고객센터 | 모델 분기, 컨텍스트 축소, 캐시 격리 |
| 컨텍스트와 메모리 | 긴 대화에서 사라진 고객의 제약 | 정보 보존, 시점별 갱신, 사용자 분리 |
| 프롬프트 인젝션 대응 | 외부 문서가 지시를 바꾸려는 상황 | 신뢰 경계, 최소 권한, 외부 전송 승인 |
| 재시도와 중복 실행 | 환불 성공 후 응답 유실 | 멱등 키, 상태 조회, 제한된 재시도 |
| AI와 함께 개발하기 | 테스트가 요구사항의 오류를 놓침 | 수용 조건, 독립된 검증, 변경 리뷰 |

실험별 4개의 연습 사례, 10개의 이해도 문제, 8개의 새 상황 복습 문제와 RAG·평가 검증 세트가 포함됩니다. RAG의 연습·검증 입력은 업무 조건에 따라 달라집니다.

## 중요한 한계

- **실제 AI 모델을 호출하지 않습니다.** API 키 없이 동작하는 결정론적 규칙 기반 시뮬레이션입니다.
- 테스트 통과는 해당 교육 시나리오의 조건을 만족했다는 뜻입니다. 실제 모델의 정확도, 안전성, 비용, 지연을 보장하거나 예측하지 않습니다.
- 모델 배정과 검색 성능 등은 학습을 위한 가정입니다. 실제 서비스에는 별도의 대표 평가셋과 운영 검증이 필요합니다.
- 학습 진행과 설계 상태는 **현재 브라우저에만 저장**합니다. 새로고침 후 복원하지만 브라우저 데이터 삭제, 다른 기기·브라우저·사이트 주소에서는 이어지지 않습니다. 저장 권한·용량 문제가 있으면 경고 후 세션 한정으로 동작합니다. 서버나 계정에 동기화하지 않습니다.
- 모든 작업 단위는 공개된 교육용 계산 규칙이며 실제 시간·토큰·비용이 아닙니다. 안전장치를 무조건 늘리면 항상 최적이라는 뜻도 아닙니다.
- RAG·평가는 합성 데이터에서 선택·판정을 계산합니다. 나머지 8개는 투명한 정책 규칙 시뮬레이션이며 실제 서버나 AI를 실행하지 않습니다.
- 메모에는 민감정보를 입력하지 마세요. 공개 GitHub에는 학습자가 작성한 브라우저 기록을 업로드하지 않습니다.
- 사이트의 소유자 전용 접근 제어는 배포 플랫폼에서 처리합니다. 앱 자체에 로그인 기능을 구현한 것은 아닙니다.

## 로컬 실행

Node.js **22.13 이상**과 npm이 필요합니다. Node.js 24 환경에서 검증했습니다.

```bash
git clone https://github.com/peacepiece7/workbench-lab.git
cd workbench-lab
npm ci
npm run dev
```

개발 서버가 출력하는 Local 주소를 브라우저에서 여세요. 기본 주소는 `http://localhost:3000/`이며 포트 사용 여부에 따라 달라질 수 있습니다.

### 검증 및 빌드

```bash
# 시나리오 규칙 검증
node --experimental-strip-types --test tests/*.test.ts

# 타입 검사
npx tsc --noEmit

# 배포용 빌드
npm run build

# 빌드한 Worker를 로컬에서 실행
npm run start
```

추가 명령: `npm run lint`는 정적 분석, `npm run format`은 코드 서식 정리를 수행합니다.

테스트는 자료 구조, 설계 조합, 문서 선택·권한 필터, 예산 상충 관계, 평가 기준 대조, 잘못된 입력, 저장·복원 및 완료 증거 보존을 검사합니다. 검증 범위와 제외 항목은 [VALIDATION.md](./VALIDATION.md)에 기록되어 있습니다.

## 기술 구성

- **React 19 · TypeScript**: 인터페이스와 학습 상태
- **Vinext · Vite**: App Router 방식의 앱 구성과 빌드
- **Tailwind CSS 4 · shadcn/Base UI**: 스타일과 접근성 기반 UI 컴포넌트
- **Lucide**: 인터페이스 아이콘
- **Cloudflare Workers · Sites**: 배포 환경 및 사이트 접근 제어
- **Node.js 기본 테스트 러너**: 시나리오 규칙 검증

별도의 AI API, 데이터베이스, 외부 결제 서비스는 사용하지 않습니다.

## 시나리오 수정

`lib/course.ts`의 `Lesson` 타입을 기준으로 자료를 구성하고 `lib/catalog.ts`에서 학습 경로를 조합합니다. 현재 자료는 **설계 변수 3개, 연습 사례 4개**로 구성합니다. RAG·평가의 심화 실행은 `lib/experiment.ts`에 별도로 구현되어 있습니다.

기본 정책 실험의 `requires`는 변수별 허용 선택지 인덱스입니다. 빈 배열은 해당 변수가 그 테스트의 판정에 영향을 주지 않는다는 뜻입니다. RAG·평가 심화 엔진은 이 목록이 아닌 문서 선택 결과와 판정 결과를 대조합니다.

```ts
// 첫 번째 변수는 1번 선택지, 두 번째 변수는 어떤 선택지든,
// 세 번째 변수는 0번 또는 2번 선택지일 때 통과합니다.
requires: [[1], [], [0, 2]]
```

선택지 인덱스는 0부터 시작합니다. 시나리오 변경 시 성공 가능한 설계가 존재하는지, 모든 변수가 의미 있는 차이를 만드는지 테스트를 실행하세요. 실험 수나 구조를 바꾸면 화면과 테스트의 고정 조건도 함께 조정해야 합니다.

## 배포와 보안

이 저장소에는 기존 사이트의 연결 정보가 포함되어 있습니다. 별도 사이트를 만들 경우 기존 `.openai/hosting.json`의 프로젝트를 그대로 대상으로 삼지 말고 새 배포 프로젝트를 연결하세요.

GitHub에 push하는 것만으로 Sites가 자동 재배포되지는 않습니다. 현재 사이트는 검증된 빌드 결과를 Sites에 게시하는 방식으로 배포되어 있습니다. README만 변경해도 이미 게시된 웹 화면에는 영향이 없습니다.

API 키, 액세스 토큰, `.env` 파일을 커밋하지 마세요. 현재 앱은 AI API 키를 필요로 하지 않으며, 빌드 출력과 의존성 디렉터리는 `.gitignore`로 제외합니다.

지원되는 브라우저에서는 선택적 WebMCP 도구 `run_learning_experiment`를 노출합니다. 수동 인터페이스와 같은 연습 실행 동작을 사용하며 이 브라우저에 실행 기록을 남깁니다. 검증 문제 실행이나 학습 완료를 대신하지 않습니다. 라이브 WebMCP 등록·호출 검증 여부는 [VALIDATION.md](./VALIDATION.md)를 참고하세요.

## 후속 범위

실제 AI 호출(P2), API 키·실행 예산 관리, 실측 비용·지연 비교, 기기 간 기록 동기화는 이번 버전에 포함하지 않습니다. 연결이 필요하면 별도 서버 측 권한·비용·데이터 전송 정책을 먼저 설계해야 합니다.
